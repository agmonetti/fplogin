# Tracking Upstream SDDM Releases and Patch Conflicts

This document describes how `fplogin` tracks upstream `sddm/sddm` releases, maintains its patch series, and handles rebase conflicts without breaking rollback or security guarantees.

## 1. Pinned Upstream Baseline

- **Upstream repository:** `https://github.com/sddm/sddm`
- **Current pinned release:** `v0.21.0` (`63780fcd79f1dbf81a30eef48c28c699ab15aded`)
- **Single source of truth for pins:**
  - `adapters/sddm/UPSTREAM.md`
  - `platforms/arch/sddm-fplogin/PKGBUILD.in` (`_commit`, `pkgver`, `pkgrel`)
  - `docs/SUPPORTED_VERSIONS.md`

Never float against upstream `develop` or `HEAD` in a release build. Every `sddm-fplogin` build is pinned to an exact Git commit hash and verified with SHA-256 patch checksums generated by `platforms/arch/sddm-fplogin/stage.sh`.

## 2. Patch Layering & Separation of Concerns

`fplogin` keeps accepted upstream-bound patches separate from distribution/packaging shims:

| Layer | Location | Purpose | Included in Upstream PR? |
|---|---|---|---|
| **Accepted core patches** | `adapters/sddm/patches/0001-*.patch`, `0002-*.patch` | Concurrent auth helpers + greeter/theme API | Yes |
| **Supplemental runtime & security patches** | `platforms/arch/sddm-fplogin/0003-*.patch`, `0004-*.patch`, `0005-*.patch` | Qt5 metatype fix, `fprintd` availability/deadline, Sprint 6 security hardening | Yes (`0003` folded into commit 2; `0004` + `0005` as commits 3–4) |
| **Distro/toolchain shims** | `platforms/arch/sddm-fplogin/0000-cmake-raise-required-version.patch` | CMake 4 compatibility on `v0.21.0` (already upstream in `228778c`) | No (dropped once upstream baseline ≥ `v0.22.0` / post-`228778c`) |
| **Arch packaging & theme** | `platforms/arch/sddm-fplogin/{PKGBUILD.in,stage.sh,merge-qt5.py}`, `platforms/arch/pam/sddm-fingerprint`, `adapters/sddm/assets/theme/` | Dual Qt6+Qt5 package assembly, PAM policy, `fplogin` theme | No |

## 3. Rebase & Conflict Resolution Workflow (New SDDM Release)

When a new upstream SDDM tag (e.g., `v0.22.0`) is released:

1. **Create an isolated workspace under `.work/sddm/`** (never `/tmp` and never modifying the accepted baseline clone):
   ```bash
   git clone --local .work/sddm/sprint7-upstream-pr .work/sddm/rebase-<tag>
   cd .work/sddm/rebase-<tag>
   git fetch upstream --tags
   git checkout -B fplogin/rebase-<tag> <new-tag-commit>
   ```
2. **Drop superseded shims:** Check whether `0000-cmake-raise-required-version.patch` (or any upstream-merged PR commits) are already present in `<new-tag-commit>` via `git merge-base --is-ancestor`.
3. **Apply patches in order using `git am -3` (or `git apply --3way`):**
   - Start from the 4-commit upstream PR series (`0001..0004` in `.work/release/upstream-pr/`).
   - Resolve conflicts manually in strict accordance with §3.2 authentication invariants (`docs/security/THREAT_MODEL.md`):
     - Never weaken `SO_PEERCRED` PID/UID validation or `QLocalServer::UserAccessOption` (`0700`).
     - Never remove `PrepareForSleep` scan cancellation, `explicit_bzero` secret wiping, or single-winner arbitration.
     - Verify `AuthMessages.h` / `Messages.h` opcode numbering does not collide with new upstream opcodes (bump protocol version / compatibility check if wire format changes).
4. **Run the full verification gate before updating any pin:**
   - Dual Qt6 + Qt5 clean build (`platforms/arch/sddm-fplogin/clean-build.sh`): 10/10 Qt6 + 9/9 Qt5 CTest suites with zero failures/skips.
   - 500-cycle helper endurance (`fd_delta=0`) and ASan+UBSan security suite (0 errors).
   - Arch PAM stack check (`tests/integration/sprint3-pam-stack-check.sh`).
   - Clean-Arch KVM E2E lifecycle (`fplogin install` → login/fallback → rollback → `fplogin uninstall`).
5. **Update pins and compatibility policy:**
   - Update `platforms/arch/sddm-fplogin/PKGBUILD.in` (`pkgver`, `pkgrel`, `_commit`), `adapters/sddm/UPSTREAM.md`, `adapters/sddm/descriptor.json` (supported version range), and `docs/SUPPORTED_VERSIONS.md`.
   - Export a verified Git bundle to `.work/checkpoints/`.

## 4. Upstream Merge Sunset Plan

Once the upstream SDDM PR (`adapters/sddm/upstream-pr/PR_DESCRIPTION.md`) is merged into an official SDDM release:

- `fplogin` marks that SDDM version as natively compatible in `adapters/sddm/adapter.json` / `cmd/fplogin-adapter-sddm`.
- `sddm-fplogin` replacement package installation becomes unnecessary on systems already running the upstream-merged SDDM release; `fplogin install` only needs to deploy `/etc/pam.d/sddm-fingerprint`, the `fplogin` theme, and drop-in config.
